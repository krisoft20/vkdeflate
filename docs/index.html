GDeflate on Any Vulkan GPU

Abstract

Games ship their assets compressed. vkdeflate unpacks them on the graphics card through Vulkan, on any vendor's card, with no driver extension. The format is GDeflate, the one behind DirectStorage and RTX IO. On an AMD Radeon RX 6650 XT the Silesia test files decode at 14.7 GB/s. The Khronos layer on the same card with the same data: 5.9 GB/s.

1. How it works

A GDeflate file is cut into pieces of 64 KB called tiles. No tile needs any other, so a graphics card decodes thousands of them at the same time. A CPU gets through a few at a time.

The figure is one file of 10 MB, the collected works of Dickens, in 156 tiles. On an RX 6650 XT the first tile alone takes 0.52 ms. All 156 in one dispatch, one job sent to the GPU, take 0.585 ms.

In exact terms: GDeflate [2] is DEFLATE [1] cut into independent 64 KB tiles, with the bits of each tile dealt over 32 lanes. vkdeflate decodes one tile per workgroup, one invocation per lane.

Why it exists

DirectStorage does this GPU decompression on Windows with Direct3D 12. Vulkan has an extension for it, VK_EXT_memory_decompression [3], and so far only NVIDIA's driver is known to have it. vkdeflate is a compute shader with a small host library around it, so all it needs is Vulkan 1.2. Two cases it is made for: a Vulkan engine that ships GDeflate assets, and a DirectStorage title ported natively to Linux or the Steam Deck.

2. Measured on two cards

GB/s is the gigabytes of decoded data that come out per second; more is faster.

The data is the Silesia corpus [5], twelve standard test files, and every decoder on a card got the same compressed bytes. The time counted is the time the GPU spends decoding. The Khronos layer [4] is Khronos's open decoder with NVIDIA's shaders. VolcanStorage is a GLSL port of Microsoft's reference shader; it was measured after four fixes, because as shipped it does not finish on the RX 6650 XT.

Read from disk and decoded into a GPU buffer, the twelve files, 212 MB, take 20 ms when the files are in the OS cache and 60 ms when they are not (RX 6650 XT, NVMe drive).

How it was measured and where it does not hold is in the write-up. To add your card, run bench.cmd or ./bench.sh from the vkdeflate-bench package of the latest release and send the CSV.

3. Use it

The whole library is one C++ header. Copy vkdeflate.h into your project, or use the CMake target or the vcpkg port.

// in one .cpp
#define VKDEFLATE_IMPLEMENTATION
#include "vkdeflate.h"

std::string err;
vkdeflate::config_t cfg;
vkdeflate::ctx_t* ctx = vkdeflate::attach(
    instance, phys, device, vkGetInstanceProcAddr, cfg, err);

vkdeflate::load_t item;
// or item.data and item.size
item.path = "rock_albedo.gdz";
// or item.buffer
item.image = image;
item.extent = {2048, 2048, 1};
vkdeflate::load(ctx, queue, queue_family, &item, 1, err);

The README has every step, the other ways in and the limits. examples/ has five short programs.
